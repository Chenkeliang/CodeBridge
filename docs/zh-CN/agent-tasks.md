# Agent定时任务、待处理与告警案件

本文说明本地功能候选，尚未合入公开主分支、发布npm或部署到现有实例。安装时请核对源码提交；包版本仍为0.1.0，不能据此判断是否包含本功能。渠道连接与已有本地计划见[渠道与任务管理](channel-automation-roadmap.md)，验证范围见[实施记录](../plans/2026-10-15-agent-task-operations.md)。

## 创建与检查

打开工作台“任务”→“Agent定时任务”→“新建定时任务”。填写名称、执行指令、Agent、绝对项目目录和执行时间。指令应说明输入、要做的事和完成标准。可勾选已对该Agent启用的Skill；任务使用真实Skill入口，不复制规则，也不自动为Agent启用Skill。

“检查并预览”显示Agent状态、Runner目录访问、Skill可见性、通知目标及接下来最多三次时间。这一步不会运行Agent或发送消息，也不会授予目录访问或操作权限。实际进入Agent前会再次检查；检查后撤销目标访问或Skill可见性，仍会阻止执行。

新任务默认暂停。保存后可先点“运行一次”，核对结果，再恢复未来调度；也可在保存时勾选启用未来调度。暂停状态允许保存尚未就绪的任务，但启用和运行必须通过检查。模型、推理强度和权限模式留空沿用原Agent配置；填写时须使用Agent实际支持的值，不会自动批准权限请求。

编辑保存检查任务版本及当前配置版本。其他页面或CLI已修改时会拒绝旧版本，保留尚未保存的输入；刷新核对后再修改。新增任务、运行、重跑和补发使用操作标识去重，网络结果不明时应使用同一标识查询或重试。

## 时间与暂停

| 输入 | 含义 |
| --- | --- |
| `每天09:00`、`daily 9` | 在所选时区每日执行 |
| `工作日09:30` | 周一至周五执行，不自动扣除法定节假日 |
| `每周一09:00` | 每周一执行 |
| `每30分钟`、`every 30m` | 按固定间隔计算下一次 |
| `30分钟后`、`in 30m` | 相对于保存时解析的一次性时间 |
| `2026-12-01T09:00:00` | 按所选时区解释的一次性时间 |
| `2026-12-01T09:00:00+08:00` | 带明确UTC偏移的一次性时间 |
| `0 9 * * 1-5` | 五段Cron，周一至周五09:00 |

时区使用IANA名称，如`Asia/Shanghai`或`America/New_York`。日历和夏令时由Croner计算，以页面预览为准；无法识别的表达会拒绝保存，不猜测自然语言。一次性相对时间保存为绝对时间，之后只改指令不会把它顺延，也不会再次触发已经执行过的一次性计划。

Bridge运行期间每15秒检查一次，不保证秒级准点。同一任务不并行，遇到上一轮尚未结束时记录跳过，不堆叠运行。服务停止后错过多个周期，可选恢复时合并补一次或跳过；“跳过”对超过计划时刻60秒的发生时间生效。暂停只阻止未来触发，不取消已开始的任务；恢复从当前时间计算未来计划，不重放暂停期间的周期。已过期的一次性任务须改时间后才能恢复调度，仍可显式运行一次。

每次执行都有独立会话和参数快照。编辑当前定义不改变旧记录；从旧记录“重新执行这次”使用当次参数创建新会话。任务排队后若超过15分钟仍未开始，沿用原队列的过期保护，需进入原会话核对并继续。中断或执行结果不明会暂停该计划，先核对实际业务结果，再明确确认重跑或恢复；系统不会自动重复未知结果的业务操作。

## 结果、通知与文件

任务详情列出运行历史；点击一条可查看计划时间、开始/结束时间、执行结果、错误、通知记录、文件和原会话。进入原会话可处理权限、继续暂停队列或取消运行。只有对应会话仍存在时才显示跳转。

目标可选仅本地、已连接且允许访问的飞书聊天或Telegram聊天；可填写已有话题。每次运行固定当时目标，编辑计划不会把历史结果补发到新目标。发送前仍按当前连接与访问规则检查；撤销访问后拒绝发送。定时任务不冒充已有聊天消息，也不参与普通会话的重复投递。

| 通知方式 | 网关自动反馈 |
| --- | --- |
| 仅最终结果 | 完成或失败后发送结果 |
| 仅异常通知 | 成功时保存本地；失败、中断和审批仍通知 |
| 开始、关键进度与结果 | 发送开始、关键阶段及终态，进度限频，避免逐条刷屏 |

审批请求始终可见。上述设置只控制网关反馈，Skill或脚本主动发送的业务内容继续遵守其原规则。渠道“已确认发送”表示平台API成功，不表示收件人已读。仅本地目标不发送聊天消息。

执行状态与结果通知状态分别保存。执行成功但通知失败，不应重跑业务：使用“仅补发已有结果”，只发送已保存正文和文件，不调用Agent。发送结果未确认可能意味着平台已收到；先查看目标聊天，必要时补发，可能产生重复消息。已确认不需补发时点“确认无需补发”，只关闭本条待处理事项，原通知记录仍保留，不伪造发送成功。服务重启不会自动重发结果不明的通知。

Agent在任务运行期间可执行：

```bash
fcb tasks output /path/to/project/report.md
```

这会登记项目内普通文件，保存当次字节副本和SHA-256校验值，单文件上限25,000,000字节。结果页下载、任务结束自动通知和手动补发使用副本，原文件后来变化不影响历史结果。文件必须显式登记；系统不会扫描或自动收集Agent产生的所有文件。仅异常通知下的成功结果保存在本地。

已有`fcb send`仍可直接发送文件；任务会先留存同一副本，并标记由Agent负责交付，结束时不再自动发送该文件。手动补发会再次发送该次全部已归档文件。飞书沿用原文件边界：原文件及归档副本的真实路径都须位于当前用户主目录下；自定义数据目录也须满足此条件。Telegram沿用原适配器规则。任务中的文件出站目标取自本次固定快照，不能由Agent改收件人；定时任务不能借用告警状态操作或成员@接口。

## 待处理

左侧“待处理”汇总活跃会话中的Agent权限请求、Runtime步骤审批、暂停队列、最近失败及任务结果通知问题，可按类型筛选和分页。读取某个来源失败会显示原因，不把不完整结果称作全部清空。

Agent权限请求针对实际请求ID，允许或拒绝只作用于当前请求；页面停留期间请求已变化会拒绝旧操作，并提示刷新，避免批准队列中的下一项。Runtime步骤审批和流程定义审核保留各自语义，在原会话处理；归档会话不作为活跃待处理展示。

任务通知问题跳转到准确的运行记录；普通失败、步骤审批及暂停队列进入原会话。核对发送后补发或确认无需补发，列表会更新；成功后的历史失败不作为本任务最新失败反复提示。

## 告警案件

“任务”→“已有计划、推送与告警”→选择飞书告警任务→“查看告警案件”。可按状态筛选、分页，查看原文、来源应用、合并消息数、首次/最近时间、结论、当前负责人/审批人及排查会话。姓名使用当前群成员目录，读取失败保留原身份并显示原因。同名成员显示身份尾号。

案件读取沿用当前群访问范围及原采集状态；打开案件不会改状态、游标、表情或触发排查。已完成的历史投递仍可定位保留的会话。切换“任务设置”和案件查看保留未保存的告警草稿。Telegram告警采集仍未支持。

## CLI与Agent入口

本机CLI与Agent注入的`fcb tasks`使用相同任务API。Bridge须已运行；本机命令使用对应数据目录中的连接配置，下面的任务与记录ID用实际查询值替换。

```bash
codebridge tasks help
codebridge tasks list
codebridge tasks preflight --file /path/to/task.json
codebridge tasks create --file /path/to/task.json --key create-report-20261201
codebridge tasks show task_REPLACE
codebridge tasks edit task_REPLACE --file /path/to/task.json
codebridge tasks run task_REPLACE --key manual-report-20261201
codebridge tasks runs task_REPLACE --offset 0
codebridge tasks result task_REPLACE taskrun_REPLACE
codebridge tasks pause task_REPLACE
codebridge tasks resume task_REPLACE
codebridge tasks resend task_REPLACE taskrun_REPLACE --key resend-report-20261201
codebridge tasks acknowledge task_REPLACE taskrun_REPLACE --key acknowledged-report-20261201
codebridge tasks retry task_REPLACE taskrun_REPLACE --key retry-report-20261201
```

任务JSON示例（替换Agent和目录后使用）：

```json
{
  "name": "每日项目报告",
  "prompt": "阅读项目中的变更，生成摘要。将报告保存到项目目录并通过fcb tasks output登记。",
  "agentId": "codex",
  "cwd": "/path/to/project",
  "skills": [],
  "schedule": "每天09:00",
  "timezone": "Asia/Shanghai",
  "enabled": false,
  "catchUp": "once",
  "notification": "result",
  "target": { "channel": "local" }
}
```

`retry`重新执行业务，`resend`只补发已有结果，`acknowledge`只确认无需补发。执行结果不明时须先核对，再在重跑/恢复命令中显式加`--acknowledge-unknown`。同一次结果不明的写操作使用原`--key`重试，避免当作新操作。非任务会话中的Agent可按明确用户指令管理计划；定时任务自身只允许读取计划和登记本次产物，禁止借本入口自行创建或改变长期计划。

## 保存位置与验收范围

任务定义、运行快照、通知和文件元数据保存在`<dataDir>/agent-tasks.sqlite`，启用WAL，数据库与侧文件仅当前用户可读写；归档文件位于`<dataDir>/agent-task-files/`。会话、执行与审批继续使用原存储。本功能未新增自动清理或删除入口；停机备份时应同时保留数据库、WAL和文件目录，并遵循原实例备份方式。

本地验收使用真实HTTP路由、SQLite、执行协调器、编译后的工作台、实际渠道适配器和模拟Agent/SDK；独立验证Web、Agent、飞书、Telegram。没有创建真实计划、调用真实模型、发送真实消息或改变现有运行实例。正式切换后还需使用专用测试聊天逐渠道核对权限、文本、文件、审批和一个完整调度周期。
