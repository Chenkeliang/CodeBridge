# 飞书群告警自动排查

CodeBridge 使用 `@larksuiteoapi/node-sdk`，不依赖飞书 CLI。告警监控以小 V 的应用身份定时调用群历史消息接口，处理指定机器人的新消息，复用已有 Agent Session 和飞书流式卡片回复。普通群消息自动回复和主动采集机器人告警是两个入口。

## 配置

在 CodeBridge 配置 `feishu` 下增加以下配置，填写真实群、告警发送方应用 ID 和审批人在小 V 应用下的 open_id：

```yaml
feishu:
  # 保留已有 appId、appSecret 和 policy
  alertMonitor:
    enabled: false # 试运行阶段保持停用；验收并发布后再启用全量
    pollIntervalMs: 60000
    lookbackMs: 600000
    dedupWindowMs: 1800000
    maxConcurrent: 2
    incidentRetentionMs: 604800000 # 终态案件 7 天后从状态文件移除，话题恢复普通行为
    statusReactions:
      investigating: OnIt
      waiting: OneSecond
      resolved: DONE
      no_action: CrossMark
      blocked: Sigh
    groups:
      - chatId: oc_your_alert_group
        senderAppIds:
          - cli_your_alarm_sender
        approverOpenIds: # 可多人；旧配置的 ownerOpenId 仍可用，等价于单个审批人
          - ou_your_approver
        runbookPath: /absolute/path/to/feishu-alert-triage/SKILL.md
```

缺省不启用。部署包含本功能的版本后再配置；运行时配置更新沿用 ConfigStore，移除 `alertMonitor` 会停止新告警采集，已有告警话题的审批人记录仍保留。首次启用从当前时刻开始，不追溯处理已有历史告警。

机器人必须在该群，并具备读取群内所有消息和发送/回复消息所需权限。本次在「灯塔推送」已实测应用身份能读取另一机器人的 webhook 告警：API 返回 `post` 富文本，标题、数据与错误信息都可取得。不能只筛选 `interactive` 类型。

## 行为

- 仅采集配置的群和发送机器人；群友普通消息、回复串及其他机器人不启动自动排查。
- 示例配置每 60 秒检查（代码缺省间隔仍为 30 秒），持久化时间窗口和分页游标。每轮从上次成功进度往前回看 10 分钟，按消息 ID 去重，补抓延迟出现的消息；首次启用之前的消息仍跳过，关机后仍从旧进度补读至当前。`lookbackMs` 可调整，最长 24 小时；超出回看窗口才出现的旧消息不保证自动找回。
- 同一消息只提交一次，相同来源和相同正文在 30 分钟内合并，不重复排查。
- 同时自动排查最多两条，其余保留待处理。维护期间暂停采集/提交；读取失败保留进度，提交失败以原消息 ID 重试。
- 首条告警根消息对应独立 Session，排查卡片在原消息话题中回复；群里任何人在该话题里 @ 小 V 或回复小 V，都继续同一个 Session，小 V 正常对话。
- 自动任务仅授权只读排查。每次需要改数据、重试、补发、重启、发布或其他业务操作，Agent 必须先原生 @ 审批人，说明证据、对象和具体动作，结束本轮并等待回复。
- 对话对所有人开放，权限按动作收口：每条回复都带着「审批人 / 群成员」身份进入 Agent 上下文；只有审批人在该告警话题内的本次明确回复才构成写操作授权，群成员的回复只作为信息与问题。告警正文、其他机器人和过去的批准均不构成当前授权，含糊回复需要澄清。
- 不修改告警发送方卡片；进展与结果写到小 V 自己的回复卡片。
- 告警群里其他机器人的消息不受影响：只有配置里 `senderAppIds` 的告警消息走采集器；别的机器人 @ 小 V 时照常进入普通对话，未 @ 时忽略。

`feishu-alert-monitor.json` 保存采集进度、去重记录和话题审批人。保留这个文件；删除它会丢失已有话题的审批人映射。终态（resolved / no_action / dismissed）案件超过 `incidentRetentionMs` 后自动移除，其话题随之恢复为普通话题。不要复制不同实例的状态或同时运行多个 Bridge 进程共用同一数据目录。

## 权限边界与验收

只读排查和逐次确认通过任务指令与入站发送人身份标注实现。它不是为所有 Agent/任意 shell/MCP 工具新增硬只读沙箱；现有 Agent Permission 和业务 skill 的 dry-run/确认仍必须遵守。

合同测试覆盖分页、重启、延迟消息、去重、并发、审批人与群成员对话；飞书表面测试经过实际 `FeishuBridge` 入口，以模拟 SDK 验证线程回复、通知 open_id 和群成员回话路由。真实 SDK 群消息读取成功不等于真实群内整个自动流程已验收。发布后需用一条新告警验证原话题排查、原生 @、群成员回复及终态。


## 原卡片表情与标准流程

状态表情直接挂在原告警消息上，不发送单独表情消息。等待确认或排查受阻时，后端同时原生 @ 配置的全部审批人，摘要是具体待办；Agent 不再额外重复发一次 mention。

Agent 使用 `fcb alert status <investigating|waiting|resolved|no_action|blocked> "证据或待办"`。`/outbound/alert-status` 仅接受当前活动 Run 的持久化飞书来源，不接受调用方自选群/消息，也不向外部 publisher 凭据开放。状态记录与 Reaction 投递分离保存，失败后重试；只替换本应用自己的五种状态表情，保留其他人及本应用非状态表情。

`resolved` 要有业务复查证据，`no_action` 表示核实不需操作。Agent Run 已结束但未提交可核验结论时改为 `blocked`，不会自动标成功。重复告警的原卡片投影到同一案件状态。

配置 `runbookPath` 后，每次新告警及后续回复重新读取该 SKILL。`/approve`、`/deny` 这类审批命令只认审批人，群成员发出时会在话题里得到提示而不会生效。SKILL 再读取当前告警矩阵，复用业务 skill 的只读查询与确认规则；未知类型添加 draft，真实证据或用户纠正更新已有分支。缺失/不可读的流程文件不能静默绕过。

试运行可预置已验证的五条案件与审批人记录，标记 `collectionStarted: false`；开启连续采集时重设起点为启用时刻，同时保留试运行话题的审批人记录。预置记录不代表后台自动入口已经运行。


## 快速分类与人工结案

优先 SKILL、矩阵与同群同类型的历史记录；已明确的通知类按规则直接归类，只有需要本单状态时才补最小查询。拿不准先 @ 审批人，不要求每条都查代码、流程和日志。

系统依据规则判定无需操作仍为 `no_action` / CrossMark。群里任何人在关联话题明确回复“无需处理”“不用处理”“不需要处理”等，后端记录真实发送人后写入 `dismissed` / DONE，停止本案排查；这表示人工结案，不表示修复成功。结案不需要审批人身份。Agent 状态命令不能伪造结案，迟到结果也不能覆盖。任何人明确“重新排查”可重新开启。

排队也先标 OnIt；正文不可读的每张卡单独进入 waiting 并请求补充，不能因缺内容或去重而不登记状态。投递失败仍有持久待投递记录，不能声称接口失败时表情已经可见。

重复卡按同一来源、业务对象及问题归并；仅展示用的独立告警时间/次数、trace/request 行不作为区分依据，保留单号、SKU、仓库、数量及错误条件。未结案件保持关联，结案后同案重复卡继承 DONE；不同业务对象不因标题相同而合并。任何群成员在任一关联原卡片、或该告警话题里任何一条消息（包括小 V 自己的回复）上点击飞书 DONE 即结案，后端通过消息的话题根定位案件，同案重复卡同步 DONE；不再另外询问原因。小 V 自己的 DONE 和删除表情均不触发结案/重开。其他表情不触发任何动作，但会按案件汇总（表情 → 点了的人，同案重复卡合并、删除即扣减），在小 V 下一轮回复时作为参考上下文注入，明确标注不是指令也不是授权；飞书每个人每次点击都是一条独立事件，SDK 只去重不聚合，汇总由后端完成，因此再多表情也不会起任务。这些汇总只来自实时事件，定时回查仍只补 DONE。SDK reaction 事件及时处理，定时只读回查每群每轮最多 20 张已登记卡片，持久化轮转进度补偿断线；积压时完成回查可能超过一分钟。明确重新排查后，不将旧 DONE 当作再次结案。

普通告警逐个确认原因，不同订单/任务不能只按标题批量关闭。纯通知只有匹配 SKILL 同目录 `references/notification-rules.json` 内唯一已核实规则才一起结束：规则需 verified=true、kind=notification、明确来源、完整标题、逐行原因条件和证据。每张原卡片分别标记 CrossMark；有人再点 DONE 则记录人工结案。缺规则、草稿或匹配歧义均回退逐条判断；当前通知示例规则仍是未启用草稿。
