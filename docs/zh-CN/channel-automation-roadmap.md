# 渠道与任务管理

本地候选已实现两个工作台入口，尚未合入公开主分支、发布 npm 或切换现有实例。版本区别见[交付状态](../release-status.md)。

## 两个入口

| 入口 | 当前候选支持 | 使用方式 |
| --- | --- | --- |
| 渠道 | 飞书、Telegram 的凭据验证、安全保存、连接应用与实时状态、访问名单、管理员；飞书群成员选择、私聊策略、自动回复或仅 @ 回复及按群例外 | 可直接在网页完成首次配置与当前机器人密钥轮换；保存后单独应用连接。初始化向导仍可使用。 |
| 任务 | Agent定时任务与运行恢复；已有本地launchd计划、固定目标推送、飞书告警及案件 | Agent任务独立列表；已有计划和告警保留原入口。详见[Agent任务使用说明](agent-tasks.md)。 |

沿用当前本机网页访问方式，不新增网页登录、跨平台统一身份、角色设计器、模板中心或流程编排器。网页的信任边界是本机操作系统用户；聊天成员继续通过各自渠道使用机器人和参与审批。

## 渠道

启动带 Web 的 Bridge 后，进入“渠道”，填写飞书 App ID/Secret 或 Telegram Bot Token。可“仅验证凭据”，或“验证并保存凭据”；保存成功清空密钥输入，只返回来源和身份，不返回旧密钥。留空保留原密钥，新输入通过系统钥匙串保存；钥匙串不可用则拒绝保存，不回退明文。然后配置允许的聊天与成员，点击“应用连接”。Telegram 首次应用前必须至少设置一位允许用户或一个允许聊天。

保存和生效分别显示为待应用、应用中、已连接、断开或失败。应用只替换当前渠道，不重启 Bridge/Runner；存在排队、执行、等待审批或尚在提交的任务时拒绝切换。新连接失败会尝试恢复旧连接，页面说明结果。状态每5秒刷新，保留尚未保存的输入。飞书握手失败后会关闭底层重连任务，避免新旧连接并存。

直接由启动环境变量管理的凭据只允许在网页验证，更新需在服务环境完成并重启。已经绑定的飞书 App ID 或 Telegram 机器人身份固定，可轮换同一机器人的密钥；更换机器人需要独立数据目录或另行设计身份与游标迁移，不能覆盖旧绑定。应用配置和权限参见[飞书说明](feishu-app-setup.md)。

管理员是渠道内的配置操作身份，告警审批人只批准对应群的操作；收件人不会因此获得审批权。飞书既有 `access.allowedUsers` 仍保留其可信操作身份，页面会明确说明。Telegram 管理员在本渠道独立配置，不从飞书身份推断。

飞书群聊回复可选择“自动回复”或“仅 @ 回复”，默认仅 @。后者仍保留直接回复机器人及已有话题的续聊，但 @ 其他成员不触发。按群例外复用 policy.scenarios，页面可查看、添加、修改、停用和移除；按列表顺序取第一个已启用的有效设置，没有匹配时使用全局模式。已有自动回复例外不会被隐藏或因修改其他渠道设置而丢失。保存由现有 ConfigStore 通知实际 Bridge 更新，无需新建会话。

飞书成员选择读取机器人已加入且符合当前访问范围的群的官方接口，返回本应用的 Open ID；也可填写已核实的原始 ID。接口失败不补造身份、不自动授权。凭据只显示来源，不返回密钥。

## 任务

- **本地计划**：明确接入当前用户 `~/Library/LaunchAgents` 中已有的计划。接入只登记，不运行或改动原脚本。可启停、显式运行一次、修改日历时间或运行间隔；保留原命令、参数、环境与其他 plist 字段。使用宿主机系统时区。运行中拒绝停用和修改；不会强制杀进程。保存计划会重载空闲任务，原有 `RunAtLoad` 等设置可能触发一次执行，页面会提示。最近退出码来自 launchd，不冒充完整业务执行历史。
- **推送**：自动显示已有 publisher；可调整固定群、话题和允许发送的内容类型，保留原凭据。签发与吊销继续由 `codebridge publisher` 完成。修改交付设置不重跑业务。
- **告警**：可新增默认停用的任务，维护来源应用、群、负责人、审批人、启停和 Skill 入口。启停只控制新采集，保留案件、游标与既有对话。失败或排查受阻时 @ 负责人；需要操作批准时 @ 审批人，两类成员可分别从群成员中选择。负责人不会自动获得审批权限。旧配置未设置负责人时沿用审批人，页面显示实际收件人，保存后可独立调整；既有案件使用当前负责人。撤销审批人后，既有案件的新审批响应也按当前群配置判断。现有采集、去重、状态表情与通知机制继续沿用；未新增 Telegram 告警采集。

告警的常用配置改为按名称选择：渠道自动使用已连接的飞书，按群名选群后自动读取成员，在姓名列表中勾选负责人。同名成员附带身份尾号，避免选错人。唯一可用群和唯一来源自动选中；已配置告警的群不会在新增时被误覆盖。任务名称默认使用“群名告警”。

告警来源从最近50条群消息中的机器人发送方识别，排除当前机器人与普通成员；页面展示近期消息帮助辨认，不把消息标题称作机器人真实名称。多来源需明确选择，未发现来源时可等新消息后刷新，或在高级设置填写已核实的应用 ID。新任务的审批人优先沿用本群中已获渠道操作身份的管理员；负责人不因此获得审批权。审批人调整、名称覆盖、Skill 路径和手工 ID 都放在高级设置，原有设置继续保留。

目录、成员和消息读取失败分别显示原因与刷新入口，不清空已保存身份；切群后忽略旧请求，并清除前一群的来源、成员和规则入口。目录查询不会自动放宽访问名单。当前采集仅支持飞书，Telegram 在告警渠道中明确显示未支持。

Agent定时任务、任务详情、补发与重跑、待处理总览和告警案件已作为本地候选接入，使用现有Run与审批机制；完整参数、通知边界、CLI与恢复方法见[使用说明](agent-tasks.md)。本地launchd计划继续由系统调度，不提供任意命令编辑器。

## 在原 Skill 中维护规则

支持标准目录 `SKILL.md` 加 `references/`、`scripts/`；告警入口可以是包根，也可以是 `groups/<group>/runbook.md`。页面列出包根说明、当前入口及同目录 `references` 的 Markdown/JSON 文件，不复制业务规则到应用仓库，不修改其他群的引用目录。脚本仍由原 Skill 工具维护。

读取允许显示已有规则的校验问题，以便修复；保存校验当前文件格式、包内引用存在性和版本。入口最多64KB，详细内容放在引用文件。跨 Skill 的既有依赖引用可保留，但本接口不读取或改写包外文件。JSON 通知规则必须可解析，且 `notification-rules.json` 含 `rules` 数组。

管理与凭据引导接口仅接受本地主机和同源请求；管理写入另检查认证和配置版本；规则与计划另检查文件版本。冲突或失败保留草稿，用户刷新后确认当前内容再保存。配置使用原子替换，失败不发布新内存状态。规则和计划覆盖前生成 AES-256-GCM 加密备份，密钥存入系统钥匙串；钥匙串不可用则不覆盖原文件。备份在 `<dataDir>/management-backups/`，原文件位置、版本和密钥引用都在备份元数据中。恢复应在停止相关新任务后由本机维护者进行，不能直接把加密 JSON 当原文件覆盖。

## 现有实例接入

本轮只做本地实现和隔离验证，没有迁移真实任务、改写业务 Skill 或更改运行配置。实际切换时先核对原计划、权限、凭据引用与案件文件；逐项接入并观察一个完整周期。沿用原调度器和状态文件，不并行创建第二套真实触发器，也不复制不同实例的案件状态。

用户自己的群、成员、密钥、本地计划、业务脚本和 Skill 留在私有运行目录；发布物只包含通用代码、格式说明及虚拟测试数据。
