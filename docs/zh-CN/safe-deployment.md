# 飞书口语安全发布

## 日常使用

与小V直接说：

- “修改 CodeBridge 的……，测试通过后上线”：Agent 在指定代码目录修改、验证、提交，随后提交准备并自动发布请求。
- “先改好，暂时别上线”：仅准备候选，不切换服务。
- “准备发布”：对已提交的当前代码独立构建、测试。
- “把刚才改的上线”：发布本会话最新准备成功的候选。如果最新准备失败，不会退而发布更旧的候选。
- “上线了吗？”：查询最新状态。
- “取消这次发布”：在切换前取消；切换已经开始时不强行中断。
- “退回上一个版本”：等待安全窗口后恢复上次保留的部署。

只接受安装时绑定的飞书负责人。引用/否定文本不当作上线授权；复杂或模糊语句不会静默授权发布，可另发一句“把刚才改的上线”。

## 工作方式

宿主机 launchd 保活独立发布器，单个发布请求只执行一次。发布请求与结果落盘；恢复时不盲目重新执行发布。Bridge/Runner 可被切换，发布器继续运行并独立通知飞书。

准备阶段：固定 Git commit → git archive 独立目录 → frozen lockfile 安装 → 全量构建和测试 → 记录校验值。工作区有未提交文件时拒绝准备。运行版本不会被源目录构建覆盖。

发布阶段：维护标记暂停新任务执行 → 等正在执行的 Run 及其回复投递完成 → 校验产物 → 保存旧 plist → 按组件切换 → 等 launchd 旧服务完全退出 → 启动 → 核验发布编号/commit、接口、飞书连接、稳定进程 → 恢复接单。长时间等待超时取消，旧服务继续工作。

失败则恢复保存的部署并验证。回滚验证失败时保留维护状态并明确通知，不伪报恢复成功。排队但尚未执行的任务不会阻塞发布，维护解除后继续派发。飞书维护期间的新消息会提示稍后重发。

数据库结构变更不自动发布；检测到迁移需单独审核。发布器和安装器自身更新也不能走普通发布，需在宿主机独立安装，保持救援入口不随业务版本一起变化。

## 初次安装（维护者）

先构建仓库，执行 scripts/install-host-deployer.mjs 的预览，确认宿主机、绝对解释器路径、数据目录与原始飞书发送者 open_id。明确 --install 后安装；敏感配置只存在权限600文件，发布器目录700。安装器不会顺带重启Bridge/Runner。

首次将业务服务接到包含发布入口的版本，随后即可在飞书发布。安装使用可工作的宿主机 Python>=3.9，不能从Linux虚拟机运行安装器，也不要临时绕过依赖检查。

发布数据位于 dataDir/deployer：config.json（凭据）、state.json（状态/通知）、maintenance.json（维护）、releases/<id>/manifest.json 和独立 app 目录、install/build/test.log。不要在飞书贴出凭据。

## 验证边界

测试覆盖所有者及原始消息授权、否定/引用、维护期现有任务继续与排队恢复、构建失败、冻结产物校验、异步bootout、准备自动发布并发、进程中断恢复、回滚、终态维护清理、通知重试不阻塞控制、最新失败候选不回退旧候选。

实际宿主机/飞书验收记录单独保存；不以测试通过代替真实部署成功。
