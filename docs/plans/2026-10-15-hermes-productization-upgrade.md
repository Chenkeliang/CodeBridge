# Hermes 参照下的产品化紧要升级

## 范围与依据

参照 Hermes 官方管理页（https://hermes-agent.nousresearch.com/docs/user-guide/features/web-dashboard）及配置说明（https://hermes-agent.nousresearch.com/docs/user-guide/configuration），对比当前源码，而非假设已有能力已发布。沿用 macOS 本地管理与现有工作台，不引入公网登录、多租户、通用流程设计器或新的调度框架。本轮只修改本地候选，不修改真实密钥、群、业务 Skill、服务或计划，不推送或部署。

## 按用户影响排序

| 优先级 | 当前差距 | 需要标准化的行为 | 本轮 |
|---|---|---|---|
| P0 | 渠道页面只管理身份和策略，凭据仍需终端 | 网页按渠道填写必需字段，留空保留原密钥，验证后安全保存，能在空闲时应用连接 | 本地完成 |
| P0 | 配置已保存不代表连接生效；Telegram未返回真实连接态 | 分开显示未配置、待应用、应用中、已连接、断开与失败；失败能重试并尽量恢复旧连接 | 本地完成 |
| P0 | 本地引导接口未校验请求主机，管理边界不足 | 仅接受本地主机和同源请求，覆盖密钥引导与管理接口 | 本地完成 |
| P0 | 默认注册演示能力，权益余额适配器会返回模拟值 | 默认启动不加载或暴露演示来源，历史登记也不得冒充可执行业务 | 本地完成 |
| P1 | 定时任务仅接入已有launchd计划 | 后续复用已有执行器补任务创建、运行与投递历史；不能把发送重试变成业务重跑 | 后续 |
| P1 | doctor、局部备份和安全发布已有机制，缺统一运维表面 | 可理解的诊断、脱敏日志、可验证的备份恢复；保留原发布排空与回滚 | 后续 |
| P1 | 模型鉴权由各Agent/现有Pi设置分管，缺统一诊断视图 | 展示实际供应商、模型、推理强度及鉴权归属，不复制一套外部CLI凭据 | 后续 |
| P1 | 告警通用指令仍混有业务领域用语 | 业务规则归外部Skill，通用层只保留状态、权限、通知与证据约束 | 后续 |
| P2 | 运行用量、成本、任务与投递归因分散 | 基于真实事件与已上报计量统一展示；缺数据时明确未知 | 后续 |
| P2 | 新使用者及贡献者仍要理解大量工程细节 | 分发版本与源码能力分清；简短上手、接口约定、扩展指南与实际演示 | 后续 |

Hermes的参考价值是把配置、密钥、渠道状态、任务与运维放到可操作页面。CodeBridge继续保留自己的Agent适配器、会话、权限和发布机制，不复制无关功能。

## 本轮约束与成功条件

1. 飞书App ID/Secret、Telegram Bot Token通过网页验证并保存；验证失败、版本冲突或钥匙串失败不覆盖原配置。密钥不回传页面、不写日志、不降级成明文。直接环境变量管理的字段明确锁定，不保存无效覆盖。
2. 新配置在应用前不更改现有连接所用的凭据。应用连接只替换目标渠道，不重启Bridge/Runner；存在执行或待提交任务时拒绝切换。新连接失败恢复旧连接并明确结果。首次配置能创建实际渠道适配器，相关查询和发送入口读取当前实例。
3. 固定已配置的机器人身份，支持当前机器人密钥轮换；更换飞书应用或Telegram机器人涉及身份、消息游标与审批绑定迁移，本轮不自动迁移、不清空旧记录。
4. Telegram首次连接仍要求已有成员或聊天允许名单。负责人、审批人、Agent Permission与发布授权不混用。
5. 仅接受本地主机和同源管理请求；不增加公网暴露入口。验证凭据只调用对应服务的认证/身份查询，不发送测试消息或启动业务任务。
6. 演示来源仅从运行时注册表隐藏，不删除用户数据库记录；真实Skill/MCP能力保留。
