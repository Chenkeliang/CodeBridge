# 飞书 CLI 与告警定向核账提醒

文中的“示例成员甲”为虚构姓名；实际群的业务矩阵与联系人规则保存在仓库外的群 SKILL 中。

## 用户目标与边界

示例告警群的重复退款核账分支在原告警话题通知示例成员甲，不再通知原审批人，也不将示例成员甲设为审批人或全群负责人。飞书 CLI 的安装检查、复用机器人应用、权限检查和按需个人授权由 CodeBridge 封装。本次不夹带严格群聊模式或未发布ACP修复。

## 实现

- 飞书通道显式依赖官方 @larksuite/cli 1.0.98。`codebridge feishu-cli` 提供 install/setup/status/login/qrcode/complete/members/search-user。运行于独立 `<dataDir>/feishu-cli` 配置目录；setup复用当前机器人应用，密钥通过stdin交给官方CLI，官方负责系统钥匙串与授权凭据。不会新建飞书应用。所有日志和结构化输出去除凭据。
- 查询本群成员明确使用bot身份；全通讯录姓名搜索明确使用user身份，缺个人授权时返回官方错误及提示。授权只申请指定scope（默认contact:user:search），先返回设备授权链接和设备码；可生成PNG二维码；用户完成后再complete。不申请全量权限、不静默替用户同意。
- 不预配置联系人；notify直接填写本群受信任矩阵指定的姓名。后端完整读取本群成员并按姓名精确匹配，同ID去重后唯一命中才投递。查不到、同名或成员读取失败时在原话题给出一次失败反馈，保持待跟进，不转发给审批人。
- 原 `/outbound/alert-status` 增加可选notify姓名。runId仍由Runner注入，群/话题由活动Run的持久化投递事实确定，不接受调用者指定目的地。发布者、无活动Run及无原话题均拒绝。
- `fcb alert status waiting --notify "示例成员甲" "核账信息"` 或内置MCP `codebridge_alert_status`（status/summary/notify）更新原卡片状态并在原告警话题原生@联系人。MCP运行在宿主机，避免shell沙箱网络影响，不新增独立通用执行器。
- 联系人选择随案件持久化，发送失败/重启仍只重试该联系人。联系人失效或不在群时明确失败，保留未投递状态，绝不退回通知审批人。通知幂等键包含所选收件人。成员校验期间若已人工结案，不回退终态或发送迟到提醒。
- 不改变审批人校验、业务写授权、默认其他告警通知及自动采集。联系人只接收核账提醒，其回复不授予写操作权限。

## 生效步骤

1. 2026-10-22用户最终确认：移除预配置联系人，按矩阵姓名自动查本群，唯一匹配再原生@；重名/查不到反馈。已授权改好验证后上线。不增加notificationContacts字段，不把用户ID写入源码或群配置；审批人及负责人不变。
2. 将示例告警类型的重复退款核账分支更新为指定notify联系人；其他分支不变。旧运行版本不支持notify，不能提前修改成调用新工具。
3. 新排查或续聊读取新提示；旧任务不会热替换。已有案件尚未确认投递，不补发/不宣称已通知。需要对已有卡片发送时先核对是否已提醒，使用同一案件避免重复。
4. 用户已明确授权验证后上线，按正式发布流程执行并核验实际commit、飞书连接与群规则。上线不会重放历史案件或用测试消息打扰核账人。

## 验证

本地测试全部使用模拟飞书SDK和本地HTTP：通知失败后重启仍只通知finance，失效联系人不回退；API拒绝伪造群和无效notify；MCP拒绝伪造runId；fcb仅传key和原Run；活跃飞书适配器确认replyTo为原卡、replyInThread=true、mentions只有联系人，联系人/approve被拒。CLI测试覆盖stdin密钥、凭据脱敏、分步授权、显式bot/user身份及二维码相对路径。

验证记录（2026-10-22）：`pnpm build`通过；`pnpm lint`为0 errors / 7个既有Web warnings。相关回归34文件/310项通过，末次补充“非群成员也保留目标避免默认回退”和人工结案并发后，重新构建并复核6文件/54项全部通过；每阶段对照最终源文件快照校验一致。真实本机CLI install/setup/status成功，bot identity verified=true，user身份missing；通过封装的members只读查询精确找到目标成员且与小V SDK返回的同应用openId一致。没有发起个人授权，没有发送真实提醒，没有修改线上通知联系人或审批人。
